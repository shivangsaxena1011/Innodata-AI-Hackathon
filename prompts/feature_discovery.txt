   it, do not propose it.
2. Tasks must differ in BEHAVIOUR (rules, state, interactions), not just names or numbers.
3. Scope: implementable in 30-200 changed lines, touching 1-3 existing modules, using only

5. Requirements must be precise enough that two engineers would write the same tests:
   state exact rules, thresholds, rounding, ordering and error types.
6. Use realistic product language (what a real user or product manager would ask for).
